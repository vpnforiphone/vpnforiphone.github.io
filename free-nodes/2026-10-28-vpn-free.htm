于是，备份——这个看似枯燥却至关重要的操作，便成了每个 Shadowrocket 用户必须掌握的“保命技能”。今天，我们不谈复杂的协议原理，也不聊玄学的测速优化，只聚焦于一个核心主题：如何系统、安全、高效地备份你的 Shadowrocket 配置，并在灾难来临时从容恢复。

一、为什么说备份是你的“数字保险单”？

在深入操作之前，我们先厘清一个底层逻辑：备份的意义，绝不仅仅是“存个文件”那么简单。

1. 对抗“熵增”的必然性
你的 Shadowrocket 配置会随着时间不断演化。今天加一个流媒体解锁节点，明天调整一条 Telegram 的分流规则，后天又更换了机场的订阅地址。这些微小的变动累积起来，就是一份极为个性化的“网络地图”。一旦丢失，你失去的不仅是几行代码，而是你过去数月甚至数年对网络环境的深度认知。

2. 应对“黑天鹅”事件
iOS 系统升级失败、手机意外进水、iCloud 同步逻辑错乱……这些不可控因素随时可能触发“配置清空”的悲剧。没有备份，你只能对着空白的配置页面欲哭无泪。

3. 多设备协同的刚需
如果你拥有 iPhone 和 iPad，或者经常需要在新手机上快速进入状态，一份完整的备份能让你在五分钟内完成所有迁移，而非花一下午重新输入节点、调整规则。

4. 试错的安全网
当你想要尝试一种激进的新规则写法，或者导入一个陌生的订阅源时，备份就是你的“撤销键”。出了问题，一键回滚，毫无心理负担。

二、备份的“三层境界”：不止于导出文件

很多用户以为备份就是“点一下导出”，实则不然。一套严谨的 Shadowrocket 备份方案，应当覆盖以下三个维度：

第一层：核心配置文件的备份（“骨架”）

这是最直观的备份对象。Shadowrocket 的“配置”页面（Config）中，每一个你下载或创建的 .conf 文件，都包含了节点的分组信息、规则集引用、代理模式设置等核心逻辑。

操作路径： 打开 App → 点击右下角“配置”标签 → 长按或左滑某个配置 → 选择“分享” → 通过 AirDrop、微信文件传输助手、邮件或 iCloud 云盘导出该 .conf 文件。

进阶提示： 不要只备份一份。建议将主用配置、备用配置、以及一些特殊场景（如仅代理模式、全局直连模式）的配置分别导出，并按照日期命名，形成版本历史。

第二层：订阅资源的备份（“血液”）

大多数用户使用 Shadowrocket 时，会通过机场订阅链接（Subscription URL）来动态获取节点列表。这个链接本身，就是一份活备份。

操作细节： 在“配置”页面顶部，点击“订阅”标签页，你会看到所有已添加的订阅。此时，请务必手动复制每一个订阅的完整 URL（包括参数部分），并粘贴到你的密码管理器或加密笔记中。

为什么不能只依赖 App 内的自动更新？ 因为订阅链接可能会因机场跑路、域名被墙或你主动更换服务商而失效。提前将链接固化到自己的安全存储中，才是万全之策。

第三层：全局设置的备份（“灵魂”）

这是最容易被忽略，但同样至关重要的一层。Shadowrocket 的“设置”页面中，包含了如“全局路由”、“DNS 设置”、“证书管理”、“Tun 模式开关”、“延迟测试方式”等数十项微调选项。

备份方法： 由于 App 并未提供“一键导出全部设置”的功能，你需要用最原始也最有效的方式——截图。按照设置页面的滚动顺序，逐屏截图，并存入一个专门的相册或加密文件夹。同时，用备忘录记录下那些非默认值的选项，尤其是你手动修改过的端口号、IPv6 开关状态等。

三、备份的“黄金法则”：频率与存储

备份频率： 建议遵循“三三制”——每次修改配置后立即备份；每周固定做一次全量备份；每月将备份文件同步至云端一份。

存储策略： 永远不要只存本地。采用“3-2-1”备份原则：本地存一份（如文件 App），外部存储存一份（如移动硬盘或 NAS），云端存一份（如 iCloud、Google Drive 或 OneDrive）。但切记，涉及敏感节点信息的备份文件，务必进行加密压缩，或直接存入支持端到端加密的笔记工具中，如 Obsidian + Cryptomator。

四、恢复的艺术：从“手忙脚乱”到“行云流水”

备份的目的在于恢复。当你拿到新手机或重装 App 后，恢复过程同样需要有条不紊。

步骤一：恢复订阅
先不要急着导入配置文件。第一步是打开“订阅”页面，点击右上角“+”，粘贴你之前保存的订阅链接。等待拉取成功后，确认节点列表已正常显示。

步骤二：导入配置
进入“配置”页面，点击右上角“+”或“导入”，选择你备份的 .conf 文件。导入后，点击该配置右侧的“!”图标，检查一下规则集是否能正常加载。如果有远程规则引用的，确保网络畅通。

步骤三：手动校准全局设置
对照你之前的截图或笔记，逐一核对设置页面中的各项开关。特别注意“证书”是否已重新信任，“DNS”是否已手动指定。

步骤四：连接测试
完成以上步骤后，开启代理，访问一个速度测试网站或直接打开 Google，确认链路通畅。如果发现某些 App 无法联网，优先检查分流规则是否生效，以及 Tunnel 模式是否开启。

五、常见误区与避坑指南

误区一：依赖 iCloud 自动备份
Shadowrocket 虽然支持 iCloud 同步，但该同步仅限于 App 内特定数据，且容易受 iCloud 服务状态影响。切勿将其作为唯一备份手段。

误区二：备份文件随意命名
建议采用“日期+用途+版本”的命名格式，例如“20231005主配置机场A.conf”，避免日后面对一堆“重命名文件”时无从下手。

误区三：忽视订阅链接中的参数
有些订阅链接附带 &flag 或 &remark 等参数，用于在 App 内显示特殊标识。复制时务必完整复制，不要人工删减。

误区四：恢复后不测试就结束
恢复完成后，至少进行 5 分钟的日常操作测试，包括打开网页、观看视频、使用社交软件，确保没有“漏网之鱼”。

六、写在最后：备份是一种习惯，而非任务

Shadowrocket 的备份，本质上是对自己网络主权的一种掌控。它不需要你具备高深的编程能力，只需要你养成一种“未雨绸缪”的习惯。每一次导出，都是对过去劳动成果的尊重；每一次恢复，都是对未来网络生活的护航。

在这个信息爆炸、节点动荡的时代，你的配置就是你的“数字资产”。别让一时的懒惰，成为日后懊悔的根源。从今天起，花十分钟完成一次完整备份，并将这个动作刻入你的数字生活仪式感中。

最后的最后，用一句话总结： 备份不会让你的网速变快，但它能让你在风暴来临时，依然拥有一座可以随时归航的避风港。

FAQ

Shadowrocket 节点测速功能如何优化游戏体验？
Shadowrocket 会定期测速节点延迟和丢包率，并结合策略组自动切换最佳节点。保证游戏流量走低延迟节点，减少延迟和掉线，提高游戏流畅度和稳定性。
Potatso Lite 支持节点手动导入和修改吗？
支持。用户可以手动输入节点信息或通过扫描二维码导入节点，并进行修改或删除。虽然不支持自动订阅更新，但足以满足轻量级用户对节点管理和分流的需求。
QuantumultX 如何使用分流策略实现广告屏蔽？
QuantumultX 可通过规则匹配广告域名或路径，将请求重定向或直接阻断。结合策略组，可实现自动屏蔽网页和应用广告，提高用户浏览体验。
VLESS + XTLS 的传输效率比 Trojan 高吗？
在高延迟环境下，VLESS + XTLS 的性能通常比 Trojan 高。XTLS 去掉了冗余加密开销，降低 CPU 占用，提高多连接场景下的吞吐率，尤其在服务器高负载情况下表现更佳。
Mellow 的 TUN 模式是否支持全局游戏加速？
支持。TUN 模式拦截系统 IP 层流量，实现全局代理，确保游戏和其他应用的 UDP/TCP 流量都走代理节点，从而降低延迟，提高游戏体验。
Sing-box 的多出口策略有什么作用？
多出口策略允许不同流量通过不同节点访问。例如视频流量通过高速节点，普通网页使用备用节点，实现资源优化与智能分流，提高网络使用体验。
Hiddify Next 的 Web 面板有什么用途？
Hiddify Next 自带 Web 管理面板，管理员可通过浏览器管理用户、监控流量、生成订阅链接并部署节点。无需命令行操作，极大提高管理效率。
Trojan-Go 与 Trojan 有什么区别？
Trojan-Go 是 Trojan 的改进版，加入了多路复用、WebSocket 和 gRPC 支持。它兼容原版配置，同时在性能和连接灵活性上更优秀，适合多环境部署。
WinXray 的多出口节点如何优化访问速度？
通过为不同流量类型设置不同出口节点，WinXray 可以自动选择延迟最低的节点处理请求。结合策略组，可提高网页访问、视频播放和游戏等应用的速度与稳定性。
Mihomo 的 Web Dashboard 有哪些功能？
Mihomo 的 Web 控制面板允许用户可视化管理节点、分流规则、日志查看与系统状态监控。可通过浏览器访问 Dashboard 地址进行远程管理，方便多设备统一控制。
